# 2026-08-16 工作日志

## 进项抵扣识别 bug 修复（专票被误判不可抵）
- 现象：用户上传的数电增值税专用发票（发票号 26442000007847305276，郭晓磊，PDF合并_第3页.pdf）被识别成不可抵扣。
- 根因（事实核查，非猜测）：该发票 `parsedData.voucherTitle` 为 undefined——它是 OCR 增强（加 voucherTitle 字段）**之前**解析的，存储缺标题。`computeDeduction` 只认 voucherTitle 判专/普，标题缺失→默认不可抵。其 rawText 含「增值税专用发票」字样，依法可抵。
- 顺带发现上次（8-15）验证的疏漏：当时只看 `rawText.split('\n')[0]`（数电票均为「电子发票」），把 8 张历史 VAT 票全误判为普票；实际其中 4 张是专票。
- 修复：
  1. `backend/src/lib/vatDeduction.ts`：新增 `deriveVoucherClassFromText`（扫 rawText 判专/普/机动车）+ `resolveVoucherInfo`，`computeDeduction` 增值税分支优先用 voucherTitle，缺失时回退扫 rawText（「专用发票」/「机动车销售统一发票」→可抵；「普通发票」→不可抵；否则安全默认不可抵）。引擎级兜底，旧数据无需重跑 OCR 即正确。
  2. `backend/local_ocr.py` `extract_voucher_title`：首条判定加「专用发票」特征词，兼容 OCR 把「增值税专用发票」切碎成多词的情况。
  3. 一次性回填脚本（已删除）：用已存 rawText 给 8 张缺标题发票重派 voucherTitle 并重算 deduction（纯 DB 操作，无需 OCR worker）。
- 验证（tsx 直连真实库）：
  - 目标发票 → voucherTitle=增值税专用发票、canDeduct=true、deductibleTax=2.38、taxRate=0.01 ✓
  - 回填 8 张（4 翻为可抵）；台账终态：18 行，可抵 14（专票4+火车票10）进项合计 ¥227.74，不可抵 4（增值税普通发票）✓
  - 后端 `tsc -p tsconfig.json --noEmit` EXIT=0。
- 教训：验证抵扣判定必须扫**整段 rawText** 的「专用/普通」特征词，不能只看首行（数电票首行恒为「电子发票」）。
