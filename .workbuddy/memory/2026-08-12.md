## 修复：/api 502 + 存档无反应
- 根因：mock 服务是后台 Bash 任务，会被 WorkBuddy 自动回收/闲置清理，8787 端口不通 → Vite 代理 `/api` 返回 502 → 上传失败、列表不变（前端 catch 有 message.error 提示，但用户感知为"没反应"）。前端代码本身无 bug。
- 解决：装 `concurrently`(-D)，package.json 加 `"dev:all": "concurrently -n web,api -c blue,green \"pnpm dev\" \"pnpm mock\""`。**以后一律用 `pnpm dev:all` 一条命令起前后端**，避免漏起 mock 再踩 502。
- 验证：dev:all 下 5173 首页 200、`/api/invoices` 经代理 200、POST 上传 201 返回 fileUrl、列表/删除正常。

## 修正：「选文件不显示 + 点存档没反应」是真 bug，非 stale tab（13:40 复查）
上一轮把用户反馈的「选文件不显示/点存档没反应」都归为 stale tab，是误判。**真实根因是前端 UploadModal 的代码 bug**：
- `<Upload fileList={fileList}>` 用的是**受控模式**，但代码只调了 `customRequest` 里的 `options.onSuccess` 和 `setSelected`，**从未通过 `onChange` 把选中文件同步回 `fileList` state**。
- antd v6 受控 Upload：传了 `fileList` 它就只显示你给的内容，自己不会往里加文件 → 所以「选了文件界面啥也不显示」。
- 连带影响：用户看到没文件、以为没附上，加上可能在跑旧页面，「点存档没反应」被放大。后端（curl 直连 / 经代理 8787→写盘 server/uploads/*.png→返回 fileUrl）早已验证全通，与本 bug 无关。

**修复**（UploadModal.tsx）：
- 新增 `onChange`：`setFileList(info.fileList.filter(f=>f.status!=='error').slice(-1))` 把内部状态同步回受控 fileList（核心修复，解决"不显示"）。
- 文件 Form.Item 加 `required` + `validateStatus/help`（无文件时红字提示"请选择发票文件"），让"没选就点存档"给出明确反馈。
- `onFinish` 兜底 `if(!selected) message.error('请先选择发票文件')` 保留。
- 验证：curl 直连 POST 上传 → 后端 201 + server/uploads 0→1 落盘，删测试记录后回 0，证明后端无问题；前端改动属受控组件同步逻辑，无需编译（用户约定改完不编译）。Vite HMR 会自动热更新，用户需**硬刷新一次**确保加载最新代码。

**经验纠正**：用户给出"选了文件不显示"这种具体 UI 现象时，应优先查前端组件状态同步（受控组件的 onChange 回写），而不是默认甩锅 stale tab。stale tab 只是叠加因素。

## 修正2：「点存档没反应」的真正根因 = `onFinish` 没挂到 `<Form>`（13:47 复查，铁证）
上一轮（13:40）修好 fileList 显示后，用户反馈「选文件有展示了，但点上传还是不行」。再读代码发现**真正的硬伤**：
- `UploadModal` 里 `<Form ...>` 上**从来没写 `onFinish={onFinish}`**。`onFinish` 函数写了（84-115 行）但没接到组件。
- 弹窗 `onOk={() => form.submit()}` → 校验通过后 antd 调 `<Form>` 的 `onFinish` → 它是 `undefined` → **什么都没发生**。所以「点存档没反应」从第一天起就是这个原因，跟 stale tab 无关（之前两轮判断都错了）。
- 修复：给 `<Form>` 补 `onFinish={onFinish}` + `onFinishFailed`（校验失败也给红字+console.warn）。

**按用户要求加了日志**（F12 → Console 可看）：
- onFinish 入口 log：ownerName/invoiceDate/hasSelected/fileType/dataUrlLen
- 未选文件 → console.warn + message.error
