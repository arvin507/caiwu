## 修复发票字段提取失败（同日晚）
- 现象：上传一份电子发票(普通发票)后，解析出的 rawText 正确，但表格字段全空。用户贴出原文（太仓京东健康有限公司 / 个人 / 发票号 26327000001391322170 / 2026年08月04日 / ¥25.90 等）。
- 根因：`extractFields` 用「标签紧贴数值」的朴素正则（如 `发票号码\s*[:：]?\s*(\d+)`），但 PDF/OFD 文本抽取丢失版式——**所有标签挤在原文前部、数值跑到末尾**，且中文标签字间被插入空格/换行（「名 称:」「销\n售\n方」），导致标签与值完全分离，正则零命中。
- 修复（`backend/src/lib/invoiceParser.ts` 的 `extractFields`）：① `labelRe` 把标签每个字符间允许空白；② `after(label, valueRe)` 先定位标签再向后搜第一个符合的值，解决标签/数值分离；③ 关键字段全局兜底——发票号 18-20 位纯数字、日期、含字母的 15-20 位税号、末尾「¥xx.xx」作价税合计、「¥金额¥税额」合并串拆金额/税额。「个人」发票识别为购买方。
- 验证：用用户原文写临时 node 脚本 `_extract_test.mjs` 跑通，输出全部字段正确（发票号/日期/销售方/税号/金额22.92/税额2.98/价税合计25.90/购买方个人），确认后删脚本、再把逻辑写回并新增 `sellerTaxId` 字段；前端 `InvoiceParsedData` 与抽屉 FIELDS 同步加「纳税人识别号」。前端类型检查通过。

## 修复日期显示格式错乱（同日晚）
- 现象：发票管理页「发票日期」「上传时间」显示为 `2026年08月12T00:00:00.000Z日`。
- 根因：`src/utils/format.ts` 的 `formatDate` 只对 `YYYY-MM-DD` 做 `split('-')`，但后端 Prisma `DateTime` 序列化返回 ISO 字符串 `2026-08-12T00:00:00.000Z`，`split('-')` 第三位变成 `12T00:00:00.000Z`，拼接出乱码。
- 修复：`formatDate` 先判断含 `T` 则 `slice(0,10)` 取日期部分再格式化，兼容「纯日期」与「ISO」两种输入；空输入返回空。同步修正 `src/types/index.ts` 中 `uploadedAt/invoiceDate` 的注释（实际为 ISO 字符串而非 YYYY-MM-DD）。
- 验证：临时 node 脚本测两种输入 + 空输入均正确，tsc 仅项目原有 `baseUrl` 弃用提示，源码零类型错误。
