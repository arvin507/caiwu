## 1. 这个模块解决什么问题

公司里最常见的报销场景有两种单据：

- **差旅费报销单**：出差产生的交通、住宿、伙食等，含「行程段」（每一段高铁/飞机一行）和「费用汇总段」（住宿/伙食/其他）。
- **一般费用报销单**：办公费、招待费、快递费等，就是一张简单的费用明细列表。

这个模块做的事：**上传 Excel → 系统自动解析成结构化数据 → 你核对 → 关联每张明细对应的发票 → 提交 → 管理员审批/付款**。

核心价值：

- 不用人工把 Excel 抄进系统，解析一步到位。
- 每张明细行都能挂一张发票，报销和发票对账一目了然。
- 状态机管住流程：草稿 → 已提交 → 已通过/已驳回 → 已付款。

## 2. 环境准备与启动（一次到位）

### 2.1 数据库（只做一次）

报销模块新增了「明细行 ↔ 发票」的关联字段（`invoiceId`）。**如果你在本机还没执行过 `db push`**，先同步表结构：

```bash
cd backend
npx prisma db push          # 把 schema 同步到 MySQL（会保留已有数据）
npx prisma generate         # 重新生成 Prisma Client（类型要用）
```

> 沙箱环境连不上你本机的 Docker MySQL，所以这一步**必须在本机终端**跑。

### 2.2 启动服务

开两个终端：

```bash
# 终端 1：后端（Next.js，端口 4000）
cd backend
pnpm dev

# 终端 2：前端（Vite，端口 5173）
cd ..
pnpm dev
```

打开 `http://localhost:5173`，用管理员账号登录（`admin / 123456`，首次需先 seed，见后端教程）。左侧菜单点「报销管理」即可。

## 3. 业务操作全流程（手把手）

### 步骤 1：上传报销单

1. 点右上角「上传报销单」。
2. 选 **报销类型**（差旅费 / 一般费用）——这决定后端走哪个解析器。
3. 选本地的 `.xlsx` 文件（≤10MB）。
4. 点「上传并解析」。系统会落盘文件 + 解析 + 写库为**草稿(draft)**，并自动弹出核对抽屉。

> 上传即落库为草稿：即使你中途关掉页面，草稿也不会丢，下次进来还能继续核对。

### 步骤 2：核对解析结果

抽屉里按区块展示（都是卡片分区）：

- **基本信息**：申请人、部门、项目、申请日期、合计金额（红色高亮）、文件名。
- **出差信息 / 行程段**（仅差旅）：出差人、起止时间地点、事由；每一段行程一行。
- **费用明细**：每条费用一行，带「发票」列。

核对无误后，点「提交（确认无误）」→ 状态变 **已提交**。

### 步骤 3：关联发票（重点功能）

每一行明细都可以挂一张发票：

1. 在明细表里找到「发票」列，点「**关联**」。
2. 弹出发票选择框，列出全部发票；已关联给其他行的会被**禁用**。
3. 选中一张 → 点「关联」，该行立刻显示「已关联」绿标。
4. 之后可点「**查看**」直接预览该发票原文件，或点「**关联**」改为「解除」来取消关联。

> 规则：**每行一张发票（1:1）**，一张发票不能同时挂两行。差旅的「行程段」和「费用明细」都支持关联。

列表页也支持：点任意报销单左侧的 ▶ 展开，直接看该单所有明细及每行发票状态，无需进抽屉。

### 步骤 4：管理员审批

管理员视角下，已提交的报销单会出现「通过 / 驳回」按钮：

- **通过**：状态 → 已通过，同时记录审批人。
- **驳回**：需填原因，状态 → 已驳回（申请人可在抽屉看到红字驳回原因）。
- 已通过的单可点「**标记付款**」→ 状态 → 已付款。

权限边界：

- 列表/详情/预览：**本人或管理员**可见。
- 审批/标记付款/删除：**本人或管理员**；其中审批动作仅管理员能发起。

## 4. 数据模型速览

四张表（详细字段见设计文档）：

```
Reimbursement (主表, 两类共用)
 ├─ 1:* ReimbursementItem     一般费用明细 / 差旅费用汇总段
 ├─ 1:1 ReimbursementTrip     仅差旅：出差信息
 └─ 1:* ReimbursementTripLeg  仅差旅：行程段（每段一行）

ReimbursementItem.invoiceId  ─┐
ReimbursementTripLeg.invoiceId ─┴─ 关联 Invoice（1:1，唯一约束）
```

关键约定：

- `totalAmount` 由系统对明细**求和**得出，不信任 Excel 里手写的大写金额。
- 金额字段用 `Decimal(10,2)`；明细 `onDelete: Cascade`，删主表自动删子表。
- 关联字段 `invoiceId String? @unique`，删除发票时 `onDelete: SetNull`（行变回「未关联」而不是报错）。

## 5. 接口清单（含发票关联）

| 方法 | 路径 | 说明 | 权限 |
|---|---|---|---|
| POST | `/api/reimbursements` | 上传 xlsx + 解析 + 落库 draft | 登录 |
| GET | `/api/reimbursements` | 列表（admin 全量 / 普通用户仅自己） | 登录 |
| GET | `/api/reimbursements/:id` | 详情（含 items/trip/legs，嵌套 invoice） | 本人/admin |
| GET | `/api/reimbursements/:id/file` | 预览原始 xlsx（带鉴权） | 本人/admin |
| DELETE | `/api/reimbursements/:id` | 删除（级联子表） | 本人/admin |
| PATCH | `/api/reimbursements/:id/status` | 状态流转 | submit=本人；approve/reject/paid=admin |
| PATCH | `/api/reimbursements/:id/link` | 关联/解除某行 ↔ 发票 | 本人/admin |
| GET | `/api/invoices/linkable` | 关联弹窗用的发票列表（标注 `linkedTo`） | 登录 |

### 5.1 上传

```bash
curl -X POST http://localhost:4000/api/reimbursements \
  -H "Authorization: Bearer $TOKEN" \
  -F "type=travel" \
  -F "file=@差旅费报销单.xlsx"
```

### 5.2 状态流转

```bash
# 提交
curl -X PATCH http://localhost:4000/api/reimbursements/$ID/status \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"action":"submit"}'

# 管理员通过
curl -X PATCH http://localhost:4000/api/reimbursements/$ID/status \
  -H "Authorization: Bearer $ADMIN_TOKEN" -H 'Content-Type: application/json' \
  -d '{"action":"approve"}'

# 驳回（需原因）
curl -X PATCH http://localhost:4000/api/reimbursements/$ID/status \
  -H "Authorization: Bearer $ADMIN_TOKEN" -H 'Content-Type: application/json' \
  -d '{"action":"reject","reason":"发票缺失"}'

# 标记付款
curl -X PATCH http://localhost:4000/api/reimbursements/$ID/status \
  -H "Authorization: Bearer $ADMIN_TOKEN" -H 'Content-Type: application/json' \
  -d '{"action":"paid"}'
```

### 5.3 关联发票

```bash
# 把某条费用明细(item) 关联到一张发票
curl -X PATCH http://localhost:4000/api/reimbursements/$ID/link \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"lineType":"item","lineId":"ITEM_ID","invoiceId":"INVOICE_ID"}'

# 解除关联（invoiceId 设为 null）
curl -X PATCH http://localhost:4000/api/reimbursements/$ID/link \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"lineType":"leg","lineId":"LEG_ID","invoiceId":null}'
```

`link` 接口的校验逻辑（后端 `route.ts`）：

1. 报销单必须存在，且调用者是本人或 admin，否则 403/404。
2. 该行（`item` 或 `leg`）必须真实属于该报销单，否则 404。
3. 关联时发票必须存在；且该发票不能被**其他行**占用（数据库 `@unique` + 接口显式查重双重保险）。
4. 返回更新后的整单（含嵌套 `invoice`），前端直接拿它替换本地数据，无需重新拉列表。

`linkable` 接口返回每张发票 + `linkedTo` 字段：

- `linkedTo: null` → 还没关联，可选。
- `linkedTo: { type, id }` → 已关联，前端据此禁用/高亮。

## 6. 前端页面与代码地图

报销模块**不进全局 store**（只本页用），数据在页面内 `fetch` + 本地 state 管理。涉及文件：

| 文件 | 作用 |
|---|---|
| `src/pages/Reimbursements/index.tsx` | 列表页：顶部 4 张状态统计卡 + 卡片包裹的表格；行可展开看明细；「发票」列支持关联/查看 |
| `src/pages/Reimbursements/UploadModal.tsx` | 上传弹窗：选类型 + 选 xlsx，`FormData` 提交 |
| `src/pages/Reimbursements/ReimbursementDetailDrawer.tsx` | 详情核对抽屉：分区卡片展示 + 状态操作按钮 + 关联发票入口 |
| `src/pages/Reimbursements/LinkInvoiceModal.tsx` | 关联发票弹窗：拉 `linkable` 列表，关联/解除/预览 |
| `src/utils/openFilePreview.ts` | 带 token 预览文件（fetch 下载 blob 打开，**不能用 `<a href>` 裸跳**，否则 401） |
| `src/types/index.ts` | `Reimbursement` / `ReimbursementItem` / `ReimbursementLeg` 类型；金额是字符串，前端用 `Number()` 处理 |

路由与菜单：`App.tsx` 注册 `/reimbursements`；`MainLayout.tsx` 加「报销管理」菜单（所有登录用户可见）。

前端调试要点：

- 后端端口 4000，前端 5173 通过 Vite 代理把 `/api` 打到 4000（见后端教程联调节）。
- 文件预览必须带 token：`openFilePreview` 用 `fetch` 带 `Authorization`，再用 `URL.createObjectURL` 打开 blob——**不能**用 `<a href>` 整页跳转（浏览器不带 token 会 401「未登录」）。

## 7. 常见问题 / 排错

**Q：上传或关联报 `P2022 ... column does not exist`？**
A：数据库表结构没同步。回到第 2.1 节，在本机执行 `cd backend && npx prisma db push`，然后**重启后端 dev server**。

**Q：点「预览」跳到 `http://localhost:.../api/.../file` 并提示未登录？**
A：说明走的是 `<a href>` 裸跳转（旧代码/浏览器缓存）。确认已用 `openFilePreview`；硬刷新 `Cmd+Shift+R` 清掉旧 JS。地址栏若出现 `/api/.../file` 整页路径，必是裸跳转，不是 `openFilePreview`（它开的是 `blob:` 链接）。

**Q：端口变成 5174 而不是 5173？**
A：启动前端时 5173 被旧 dev server 占用，Vite 自动换了端口。本机执行 `lsof -ti :5173 | xargs kill -9` 清掉旧的再重启即可。

**Q：发票关联后列表不刷新？**
A：关联接口返回最新整单，前端会把对应行就地替换；若没反应，检查是否硬刷新过、后端是否重启（db push 后必须重启）。

**Q：一张发票想关联两行？**
A：当前设计是 1:1（唯一约束），不允许。如需一行多发票，要改成中间表，属需求变更。
