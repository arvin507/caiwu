## 第1章 这个项目到底是什么

一句话：**一个用 React + TypeScript 写的网页版"财务管理系统"**。目前实现了：登录、仪表盘（占位）、账单明细（占位）、账户管理（占位）、**发票管理（真实可用：上传、列表、排序、预览、删除）**、统计报表（占位）、系统设置（占位）。

你通过它学到的不是"怎么记账"，而是**现代前端工程是怎么搭起来的**：

- 用 **Vite** 当构建工具（负责把你的代码变成浏览器能跑的东西）。
- 用 **React 19** 写界面（组件化，像搭乐高）。
- 用 **TypeScript** 给数据上"类型保险"（写错字段名、传错类型，编辑器/编译期就拦你）。
- 用 **antd（Ant Design）v6** 当 UI 组件库（按钮、表单、表格、弹窗……不用自己画）。
- 用 **react-router-dom v7** 做路由（不同网址显示不同页面）。
- 用 **Zustand** 做全局状态（登录用户、发票列表这种"多个页面都要用"的数据）。
- 用 **Node 内置 http** 写了一个零依赖的 mock 后端（让上传/预览真实落盘，纯前端练习也能跑通全链路）。

## 第2章 项目搭建：脚手架怎么来的

### 2.1 Vite 是什么（类比）

想象你要装修一套房子：
- **HTML/CSS/JS** 是砖块、水泥、电线——最原始的材料。
- **Vite** 是"毛坯房 + 一套现代化工具箱"。它给你：本地开发服务器（改完代码秒级刷新）、打包工具（把一堆文件压缩成一个能上线的包）、对 React/TS 的原生支持。

你不需要从"一块砖"开始，Vite 的模板已经把墙砌好了，你只管往里填业务。

这个项目用的是官方 `react-ts` 模板的升级版，自带：
- React 19
- TypeScript 6
- **oxlint**（一个很快的 JS/TS 检查工具，替代 ESLint 的部分职责）
- `@vitejs/plugin-react` + `babel-plugin-react-compiler`（React 编译器，自动优化性能，新手知道有这回事即可）

### 2.2 依赖装哪里：pnpm 与 node_modules

装依赖用 `pnpm`（类似 npm，但更省磁盘、更严格）。执行 `pnpm install` 后，所有第三方库会下载到 `node_modules/` 目录。你的代码 `import antd from 'antd'` 就是从这里找的。

> **注意**：pnpm 是"严格隔离"的。A 依赖的库，B 不能直接用，必须自己声明。这就是为什么后面踩到"dayjs 没装"的坑。

### 2.3 目录结构（大脑地图）

```
caiwu/
├─ index.html              # 网页入口（浏览器第一个加载的文件）
├─ package.json            # 项目说明书：依赖 + 命令脚本
├─ vite.config.ts          # Vite 配置（路径别名、代理）
├─ tsconfig.app.json       # TypeScript 配置（给 src 用的）
├─ server/
│  └─ index.js             # 零依赖 mock 后端（端口 8787）
├─ src/                    # 你的全部前端代码
│  ├─ main.tsx             # 程序启动入口
│  ├─ App.tsx              # 根组件（路由守卫 + 全局配置）
│  ├─ types/index.ts       # 领域模型（数据结构契约）
│  ├─ store/useAppStore.ts # 全局状态（Zustand）
│  ├─ mock/data.ts         # 假数据
│  ├─ layouts/MainLayout.tsx # 整体框架布局
│  ├─ pages/               # 各个页面
│  │  ├─ Login.tsx
│  │  ├─ Invoices/index.tsx
│  │  └─ Invoices/UploadModal.tsx   # ★本次 bug 主战场
│  └─ utils/format.ts      # 工具函数
└─ docs/                   # 本教材
```

**约定**：页面统一放 `pages/`。一个页面如果只有一个文件，就叫 `Foo.tsx`；如果有很多配套文件（比如页面 + 它的弹窗），就建一个文件夹 `Foo/`，里面用 `index.tsx` 当主文件。本项目 `Invoices/` 就是这种"文件夹形式"。

## 第3章 参数与配置（逐个文件讲）

很多新手最怕配置文件，因为它们"看起来什么都不做，却又不能没有"。下面逐行拆。

### 3.1 package.json（项目说明书）

```json
{
  "scripts": {
    "dev": "vite",                                   // 启动前端开发服务器（5173）
    "build": "tsc -b && vite build",                 // 编译 + 打包上线
    "lint": "oxlint",                                // 代码风格/错误检查
    "preview": "vite preview",                       // 本地预览打包结果
    "mock": "node server/index.js",                  // 启动 mock 后端（8787）
    "dev:all": "concurrently \"pnpm dev\" \"pnpm mock\"" // ★一条命令同时起前后端
  },
  "dependencies": { ... 运行时必须 },
  "devDependencies": { ... 只在开发时用 }
}
```

**关键认知**：
- `scripts` 是"快捷键"。你在终端敲 `pnpm dev`，实际执行的是 `vite`。
- `dependencies`（依赖）vs `devDependencies`（开发依赖）：
  - `react`、`antd`、`zustand`、`react-router-dom`、`dayjs` 是**运行时依赖**——用户打开网页时浏览器要用的。
  - `vite`、`typescript`、`oxlint`、`concurrently` 是**开发依赖**——只有你写代码、打包时才用，用户用不到。
- `dev:all` 用了 `concurrently` 这个库，作用是"让两个命令（`pnpm dev` 和 `pnpm mock`）在一个终端里同时跑"。**本项目务必用它**，否则容易只起了前端、忘了起后端，然后各种 502（详见第 11 章坑6）。

### 3.2 vite.config.ts（Vite 配置）

```ts
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'
import { fileURLToPath, URL } from 'node:url'

export default defineConfig({
  plugins: [react()],
  resolve: {
    // ① 路径别名：用 @/ 代替 ../../ 这种相对路径
    alias: {
      '@': fileURLToPath(new URL('./src', import.meta.url)),
    },
  },
  server: {
    // ② 开发代理：前端写 /api/... 会被转发到 http://localhost:8787
    proxy: {
      '/api': 'http://localhost:8787',
    },
  },
})
```

**两处重点**：

① **路径别名 `@/`**：没有它，你从 `src/pages/Invoices/UploadModal.tsx` 引入 store 得写 `import ... from '../../../store/useAppStore'`，又长又容易错。有了别名，统一写 `import ... from '@/store/useAppStore'`，从项目任何位置都一眼看懂。
> 注意：别名要**两处都配**——Vite 这里配一次（让打包器认识 `@`），`tsconfig.app.json` 里还要配一次（让 TypeScript 认识 `@`，否则编辑器报错）。这就是"配置成对出现"的典型。

② **代理 `proxy`**：前端跑在 `5173`，后端跑在 `8787`，是两个不同的"源"。浏览器出于安全有"跨域限制"（CORS），直接 `fetch('http://localhost:8787/api/...')` 可能被拦。用代理后，前端只写相对路径 `/api/invoices`，Vite 在开发服务器里悄悄把它转发到 `8787`——**前端以为在和自己说话，其实是 Vite 帮忙转给了后端**，跨域问题就这么绕过去了。

### 3.3 tsconfig.app.json（TypeScript 配置，节选）

```json
{
  "compilerOptions": {
    "jsx": "react-jsx",            // 让你能直接写 <App/> 这种 JSX 语法
    "moduleResolution": "bundler", // 配合 Vite 的模块解析规则
    "noEmit": true,                // 只检查类型，不输出文件（输出交给 Vite）
    "baseUrl": ".",
    "paths": { "@/*": ["./src/*"] },// ③ 路径别名的 TS 侧配置（对应 3.2 的①）
    "noUnusedLocals": true,        // ④ 有声明但没用到的变量？报错
    "noUnusedParameters": true     // ④ 没用到的函数参数？报错
  },
  "include": ["src"]
}
```

③ 见 3.2 说明，必须和 Vite 配对。
④ `noUnusedLocals`/`noUnusedParameters` 是"强迫症开关"：你写了 `const x = 1` 但从来没用过，编译就报错。对新手是好事——逼你把没用的代码删掉，也避免手滑写错变量名。

### 3.4 index.html 与 main.tsx（入口）

`index.html` 里有个 `<div id="root"></div>`，这是 React 要把界面"画"进去的画布。

`main.tsx` 是程序真正启动的地方：

```tsx
import { StrictMode } from 'react'
import { createRoot } from 'react-dom/client'
import 'antd/dist/reset.css'   // antd 样式重置，必须在业务样式之前引入
import './index.css'
import App from './App.tsx'

createRoot(document.getElementById('root')!).render(
  <StrictMode>
    <App />
  </StrictMode>,
)
```

- `createRoot(...).render(<App/>)`：把 `<App/>` 组件渲染到那个 `root`  div 里。
- `<StrictMode>`：React 的"严格模式"，开发时会帮你多跑一遍某些检查、提前暴露问题（注意它有时会让 `console.log` 打印两次，属正常）。
- `document.getElementById('root')!` 末尾的 `!` 是 TypeScript 的"非空断言"——告诉 TS"这里一定有这个元素，别担心它是 null"。

| **zustand** | 5 | 小区共享公告栏 | 跨页面共享状态（登录用户、发票列表） |

## 第5章 TypeScript 知识

TypeScript = JavaScript + 类型。新手最大的收益是：**写错的地方，编辑器立刻画红线**，不用等到运行时才崩。

### 5.1 interface / type：给数据画"结构图"

在 `src/types/index.ts` 里，我们用 `interface` 定义"发票"长什么样：

```ts
export interface Invoice {
  id: string
  ownerName: string          // 归属人（必填）
  fileName: string
  fileType: string
  fileUrl?: string           // 加 ? 表示"可选"，可以没有
  uploadedAt: string
  invoiceDate: string
  note?: string
}
```

`?` 是"可选字段"。`fileUrl?: string` 意思是"可以有，也可以没有"。这正好对应现实：发票刚上传完后端才给 `fileUrl`，纯前端构造时可能还没有。

`type` 用来定义"值的种类"，比如：

```ts
export type TransactionType = 'income' | 'expense'   // 只能是这两个字符串之一
export type InvoiceSortKey = 'uploadedAt' | 'invoiceDate'
```

这叫**联合类型**。你写 `'foo'` 就会报错，因为不在允许的集合里。

### 5.2 泛型：能装任意类型的"盒子"

```ts
const [fileList, setFileList] = useState<UploadFile[]>([])
```

`useState<T>` 里的 `<UploadFile[]>` 就是泛型参数：告诉 `useState`"我这个状态是 `UploadFile` 组成的数组"。这样后面 `fileList[0].name` 编辑器都知道 `.name` 存在，不会误报。

### 5.3 类型推导：能推断的就别手写

```ts
const onFinish = (values: { ownerName: string; invoiceDate: dayjs.Dayjs }) => { ... }
```

这里 `values` 的类型是我们手写的。但很多时候 TS 能从上下文推出来，比如 `const total = balance + 100`，TS 知道 `total` 是 `number`，不用你写。

### 5.4 as 断言：我比 TS 更懂这个值的类型

```ts
const file = options.file as File
```

`options.file` 的类型可能是宽泛的 `RcFile | null`，但我们知道它就是浏览器选中的 `File`，所以用 `as File` 告诉 TS"按 File 处理"。**滥用 `as` 会绕过安全检查**，只在你确实有把握时用。

### 5.5 为什么 strict 模式对新手是朋友

`tsconfig` 里那些 `noUnusedLocals`、`strict`（隐含）等，本质是在**编译期拦住你**。新手常觉得"怎么老报错"，但这些报错省下的是"上线后用户看到的白屏"。把 TS 当安检员，而不是绊脚石。

## 第6章 React 知识

### 6.1 组件与 JSX

React 把界面拆成一个个**组件**（函数），每个组件返回一段 JSX（长得像 HTML 的语法）：

```tsx
export default function Login() {
  return <div>你好</div>   // JSX
}
```

`<div>`、`<Button>` 都是"标签"，但 `<Button>` 是我们从 antd 引入的组件，不是原生 HTML。React 会把它们渲染成真正的 DOM。

### 6.2 Hooks：组件里的"魔法钩子"

- **`useState`**：给组件一块"记忆"。

  ```tsx
  const [collapsed, setCollapsed] = useState(false)
  ```
  `collapsed` 是当前值，`setCollapsed` 是修改它的函数。点一下菜单折叠，`setCollapsed(true)`，组件重新渲染，菜单就收起来了。

- **`useEffect`**：组件"挂载/更新时做点副作用"。

  ```tsx
  useEffect(() => {
    loadInvoices()          // 进入发票页时，从后端拉一次列表
  }, [loadInvoices])
  ```
  第二个参数是"依赖数组"——里面的东西变了，这个函数就重新跑。空数组 `[]` 表示"只在挂载时跑一次"。本项目发票页用它来一进页面就拉数据。

### 6.3 受控组件 vs 非受控组件（重点，跟第 11 章的坑强相关）

这是个新手极易迷糊的概念，先用输入框理解：

- **非受控**：输入框自己管自己的值，你要值时去"问"它（`ref` 拿）。
- **受控**：值由 React 的 state 说了算，输入框只是"显示 state 的样子"，用户输入时通过 `onChange` 把新值写回 state。

```tsx
// 受控输入框
const [name, setName] = useState('')
<input value={name} onChange={(e) => setName(e.target.value)} />
```

**关键结论（划重点）**：一旦你把一个组件的"值/列表"用 state 接管（受控），你就**必须同时提供更新这个 state 的途径**（通常是 `onChange`）。否则组件永远显示你给的旧值，输入/选择都"没反应"。

> 第 11 章的**坑4（选文件不显示）**和**坑5（点存档没反应）**，本质都是"受控了却没接好对应的回调"。这一节是理解那两个坑的理论基础，请务必吃透。

### 6.4 条件渲染：用代码决定显示什么

```tsx
{isAuthenticated ? <系统主页/> : <Login/>}
```

`? :` 三元表达式。登录了显示系统，没登录显示登录页——这就是**路由守卫**的雏形（第 7 章细讲）。

### 6.5 列表渲染与 key

```tsx
{rows.map((row) => <Table.Row key={row.id} ... />)}
```

用 `.map` 把数组变成一串组件。`key` 是 React 用来识别"哪一行是哪一行"的身份证，**一定要稳定唯一**（用 id，别用数组下标）。

## 第7章 路由（前端里的"分机号"）

### 7.1 路由是什么

公司前台有分机号：拨 `801` 找财务，拨 `802` 找人事。网站同理：访问 `/invoices` 显示发票页，访问 `/dashboard` 显示仪表盘。**把"网址"映射到"页面组件"，就是路由。**

### 7.2 本项目怎么配路由

在 `App.tsx` 里：

```tsx
import { BrowserRouter, Routes, Route, Navigate } from 'react-router-dom'

<BrowserRouter>
  <Routes>
    <Route path="/" element={<MainLayout />}>
      <Route index element={<Navigate to="/dashboard" replace />} />
      <Route path="dashboard" element={<Dashboard />} />
      <Route path="invoices" element={<Invoices />} />
      {/* ... 其他页面 ... */}
      <Route path="*" element={<Navigate to="/dashboard" replace />} />
    </Route>
  </Routes>
</BrowserRouter>
```

- **`BrowserRouter`**：开启"浏览器地址栏路由"模式（网址是干净的 `/invoices`，而不是 `#/invoices`）。
- **`Routes` + `Route`**：路由表。`path` 是网址片段，`element` 是对应的页面。
- **嵌套路由**：`"/"` 这个父路由的 `element` 是 `<MainLayout/>`，它内部用 `<Outlet/>`（见 7.3）当"插槽"，子路由 `dashboard`、`invoices` 等会渲染进这个插槽。这样所有页面都共享左侧菜单 + 顶栏。
- **`Navigate`**：重定向。访问根路径 `/` 时自动跳到 `/dashboard`；访问不存在的路径 `*` 也跳回仪表盘。

### 7.3 Outlet：父布局里的"内容插槽"

`MainLayout.tsx` 的右侧内容区：

```tsx
<Content style={{ margin: 24 }}>
  <Outlet />   {/* 当前子路由的页面，渲染在这里 */}
</Content>
```

`MainLayout` 是壳，`Outlet` 是壳里会"换片"的屏幕。

### 7.4 useNavigate / useLocation：跳转与读地址

```tsx
const navigate = useNavigate()
const location = useLocation()

// 菜单点击 -> 跳转到对应路由
onClick={({ key }) => navigate(key)}

// 菜单选中态跟随地址栏
<Menu selectedKeys={[location.pathname]} ... />
```

`navigate('/invoices')` 等价于"在地址栏输入这个网址并回车"。`location.pathname` 是当前网址路径，用来高亮当前菜单。

### 7.5 登录守卫（用条件渲染实现）

回到 `App.tsx`：

```tsx
{isAuthenticated ? (
  <BrowserRouter>...系统路由...</BrowserRouter>
) : (
  <Login />
)}
```

没登录就根本不挂载路由，只显示 `<Login/>`。登录成功后 `store.login` 把 `isAuthenticated` 改成 `true`，组件重渲染，自动切到系统主页——**不需要手动写跳转代码**。这就是"声明式"的魅力：你描述"应该是什么样"，React 负责"怎么变成那样"。

## 第8章 状态管理 Zustand

### 8.1 为什么需要"全局状态"

有些数据**多个页面都要用**：比如"当前登录用户"（顶栏要显示，退出登录要清除）、"发票列表"（上传页往里加，列表页读出来显示）。如果只放在某个组件的 `useState` 里，别的组件够不着。

解决方案：把这些共享数据放进一个**全局仓库（store）**。Zustand 就是一个轻量的仓库。

### 8.2 怎么用

`src/store/useAppStore.ts`：

```ts
import { create } from 'zustand'

export const useAppStore = create((set) => ({
  // —— 数据 ——
  invoices: [],
  currentUser: null,
  isAuthenticated: false,

  // —— 操作（actions）——
  login: (username) =>
    set({ currentUser: { id: 'u', name: username }, isAuthenticated: true }),

  addInvoice: async (input) => {
    const res = await fetch('/api/invoices', { method: 'POST', ... })
    const saved = await res.json()
    set((state) => ({ invoices: [saved, ...state.invoices] }))
  },
}))
```

任何组件这样取用：

```tsx
const invoices = useAppStore((s) => s.invoices)
const addInvoice = useAppStore((s) => s.addInvoice)
```

`(s) => s.invoices` 是**选择器**：我只订阅 `invoices` 这一段。它变了我才重渲染，别的字段变了我不管——比把整个 store 当 props 传来传去高效得多。

> **心智模型**：store 像个全局公告栏。`set(...)` 是"更新公告"，组件用 `useAppStore(s => s.xxx)` 是"订阅某条公告"。公告变了，订阅者自动重画。

## 第9章 antd 组件实战要点

antd 提供大量现成组件，本项目用到：`ConfigProvider`、`App`、`Layout`(Sider/Header/Content)、`Menu`、`Dropdown`、`Avatar`、`Form`/`Form.Item`、`Input`、`DatePicker`、`Upload`、`Table`、`Segmented`、`Empty`、`Modal`、`Button`、`Card`、`Typography`、`message`。

挑几个和本次实战强相关的讲。

### 9.1 ConfigProvider + App 上下文 + message

`App.tsx`：

```tsx
<ConfigProvider locale={zhCN} theme={{ token: { colorPrimary: '#1677ff' } }}>
  <AntApp>            {/* 注意：是 antd 的 App，不是你的 App 组件 */}
    {体系路由或 Login}
  </AntApp>
</ConfigProvider>
```

- `ConfigProvider`：全局配置，比如中文语言包 `zhCN`、主题色。
- `AntApp`：提供 `message`/`notification` 的**上下文**。在 v6 里，弹提示要用 `App.useApp()` 拿 `message`，而不是旧式的静态 `message.success(...)`。本项目 `UploadModal` 里就是：

  ```tsx
  import { App } from 'antd'
  const { message } = App.useApp()
  message.success('发票已存档')
  ```

  如果忘了用 `<AntApp>` 包裹，这行会告警甚至不显示。

### 9.2 Form / Form.Item + rules

antd 的表单是"受控 + 校验"的集大成者：

```tsx
<Form form={form} onFinish={onFinish}>     {/* ★ onFinish 必须接到 Form 上！ */}
  <Form.Item
    name="ownerName"
    rules={[{ required: true, whitespace: true, message: '请填写归属人' }]}
  >
    <Input placeholder="这张发票是谁的" />
  </Form.Item>
</Form>
```

- `name="ownerName"`：把输入框的值登记到表单里，提交时一次性拿到。
- `rules`：校验规则。`required: true` 表示必填；不填就提交，会显示 `message` 红字且不触发 `onFinish`。
- **`onFinish`**：表单校验**全部通过**后，点提交（或 `form.submit()`）才会调用它。你在这里拿 `values` 去发请求。

> ⚠️ **本次最致命的坑就在这**：`UploadModal` 最初**漏写了 `onFinish={onFinish}`**。函数 `onFinish` 明明写好了，却没接到 `<Form>`。结果 `form.submit()` 校验通过后去找 `<Form>` 的 `onFinish`，发现是 `undefined` —— **什么都不做**。"点存档没反应"从第一天起就是这个原因。对比 `Login.tsx` 第 45 行**正确写了 `onFinish={onFinish}`**，同一个项目两种写法并存，bug 就这么藏住了。（详见第 11、12 章）

### 9.3 Upload：受控 fileList + customRequest + onChange（★本项目核心难点）

上传组件是把前面"受控组件"理论用到极致的地方。本项目最终能跑通的写法：

```tsx
const [fileList, setFileList] = useState<UploadFile[]>([])
const [selected, setSelected] = useState<SelectedFile | null>(null)

// ① 完全接管上传过程（antd 不再自动发请求，我们手动读成 base64）
const customRequest: UploadProps['customRequest'] = (options) => {
  const file = options.file as File
  // 校验类型、大小...
  const reader = new FileReader()
  reader.onload = () => {
    setSelected({ name: file.name, type: file.type, dataUrl: reader.result as string })
    options.onSuccess?.({})          // 告诉 antd：这个文件"上传成功"了
  }
  reader.readAsDataURL(file)
}

// ② 把 antd 内部的文件状态同步回受控的 fileList（★坑4 的修复点）
const handleChange: UploadProps['onChange'] = (info) => {
  const next = info.fileList.filter((f) => f.status !== 'error')
  setFileList(next.slice(-1))
}

<Upload
  accept="image/*,application/pdf"
  maxCount={1}
  fileList={fileList}          // 受控：显示什么由我 state 决定
  customRequest={customRequest}
  onChange={handleChange}      // 必须接 onChange，否则 fileList 永远空
  onRemove={() => { setSelected(null); return true }}
>
  <Button>选择文件</Button>
</Upload>
```

**为什么这么绕？** 因为我们要把文件转成 base64 存到后端，而不是让 antd 自己发一个"文件上传请求"。所以：
- 用 `customRequest` 接管，自己在里面读文件、标记成功。
- 但同时 `fileList` 是受控的（我们传了 `fileList={fileList}`），**就必须用 `onChange` 把 antd 产生的文件状态写回 `fileList`**，否则界面永远不显示已选文件（坑4）。

两个回调各管一摊：`customRequest` 负责"读文件内容 + 标记成功"，`onChange` 负责"让界面显示出来"。**少接任何一个，都会表现为某种'没反应'**。

### 9.4 Table / Segmented / Empty / Modal / DatePicker（简述）

- **`Table`**：表格。`dataSource` 给数据，`columns` 给列定义，`render` 可自定义单元格（比如预览列渲染成链接）。本项目用它显示发票列表，并支持排序。
- **`Segmented`**：分段控制器。本项目用它切换"按最新上传 / 按发票日期"排序。
- **`Empty`**：空状态。没数据时显示引导文案"还没有发票，点击上传第一张"。
- **`Modal`**：弹窗。`open` 控制显隐，`onOk` 是点确定，`onCancel` 是点取消/关闭。本项目上传弹窗的"存档"按钮就是 Modal 的 `onOk`，它内部调 `form.submit()`。
- **`DatePicker`**：日期选择器。依赖 `dayjs`（见坑3）。

## 第10章 前后端联调与 mock 服务

### 10.1 为什么要有 mock 后端

纯前端练习时，你还没有真正的服务器。但上传文件要"存起来"、列表要"读出来"，这些都需要一个后端。于是我们**自己写一个超简单后端**，专门在本地配合练习。这就是 mock（模拟）服务。

### 10.2 零依赖 Node http 服务（server/index.js）

它只用 Node 自带的 `http` 模块，不装任何第三方库。端口 `8787`。核心接口：

```
GET    /api/invoices            -> 列出全部发票
POST   /api/invoices            -> 上传一张（JSON 里带 base64 文件内容）
GET    /api/invoices/:id/file   -> 预览/下载该文件
DELETE /api/invoices/:id        -> 删除一张
```

上传时前端把文件转成 base64 字符串放在 JSON 里发过来，后端解码、写进 `server/uploads/` 目录落盘，并把元数据（归属人、日期、fileUrl 等）写进 `server/data/invoices.json`。

### 10.3 前端怎么连（fetch + 代理）

```ts
// store 里
const res = await fetch('/api/invoices', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify(input),   // input 含 base64
})
```

注意是**相对路径 `/api/invoices`**，没有写 `http://localhost:8787`。因为第 3.2 节的 Vite 代理会把它转发到后端。这就是"前端专心写业务，跨域交给代理"的做法。

### 10.4 用一条命令起前后端

```bash
pnpm dev:all
```

它用 `concurrently` 同时跑 `pnpm dev`（前端 5173）和 `pnpm mock`（后端 8787）。**务必用这个**，别只起前端——否则后端没跑，所有 `/api` 请求都会 502（坑6）。

## 第11章 本次实战踩的坑（错误清单）

以下都是本项目真实发生过的，按出现顺序，逐条说明"现象 / 原因 / 修法"。

### 坑1：装到了 antd v6，不是计划中的 v5
- **现象**：最初按"React19 需要 v5 补丁"的思路装了 `@ant-design/v5-patch-for-react-19`。
- **原因/修法**：antd v6 原生支持 React 19，那个补丁是 v5 专用的。最终**移除补丁依赖**，确认用 v6。提醒：技术栈版本是配套的。

### 坑2：antd v6 的 Input 不支持 `prefix`
- **现象**：想给输入框加左侧图标，写 `prefix=` 报错。
- **原因**：v6 里 `Input`/`Input.Password` 不支持 `prefix`（只有 `Input.Search` 支持）。改回普通 `Input`。

### 坑3：dayjs 需要显式安装
- **现象**：用了 `DatePicker` 却报 `dayjs` 找不到。
- **原因**：pnpm 严格隔离，antd 依赖的 dayjs 不会被你的代码直接引用到。修法：`pnpm add dayjs` 把它变成你的直接依赖。

### 坑4：选了文件，界面不显示（受控 fileList 没同步）★核心
- **现象**：点"选择文件"，文件对话框能选，但选完界面上什么都没有。
- **原因**：`<Upload fileList={fileList}>` 是**受控模式**，我们却只在 `customRequest` 里调 `onSuccess`，**从没用 `onChange` 把选中文件写回 `fileList`**。受控组件只显示你给的 state，你不更新它就永远空。
- **修法**：加 `onChange`，把 `info.fileList`（过滤掉失败项）同步回 `setFileList`。这是"受控了就必须接 onChange"的铁律体现。

### 坑5：`onFinish` 没挂到 `<Form>`，点存档没反应 ★最致命
- **现象**：填好表单、选好文件，点"存档"毫无反应，不报错也不上传。
- **原因**：`UploadModal` 的 `<Form>` 上**漏写了 `onFinish={onFinish}`**。`onFinish` 函数本体写好了，但没接到组件。点"存档"→ Modal 的 `onOk` 调 `form.submit()` → 校验通过后去找 `<Form>` 的 `onFinish` → 它是 `undefined` → **什么都不发生**。
- **修法**：给 `<Form>` 补 `onFinish={onFinish}`，并加 `onFinishFailed` 兜底（校验不过也给提示）。
- **对照**：同项目的 `Login.tsx` 第 45 行**正确写了 `onFinish={onFinish}`**。两种写法并存，正是 bug 难以察觉的原因。

### 坑6：mock 服务被回收，导致 /api 502
- **现象**：前端报 502，列表空，上传失败。
- **原因**：mock 后端是后台任务，闲置时会被环境回收，`8787` 端口不通，Vite 代理转发过去就 502。
- **修法**：装 `concurrently`，用 `pnpm dev:all` 一条命令同时管前后端；遇到 502 先确认 `8787` 是否还活着。

### 坑7（本次新加）：缺少日志，靠"猜"排查
- 早期排查全靠"后端 curl 通了，那前端应该没问题"的假设，没有在浏览器里拿到真实证据。直到用户要求"加日志别瞎猜"，才在 `onFinish` 各步加了 `console.log/error`，并在 `F12 → Console` 拿到第一手现场。

## 第12章 为什么这些错误一直没查出来（方法论反思）

这一章是你特别要求的，也是最有价值的。我们**诚实复盘**：前面两轮为什么把"点存档没反应"反复归咎于"浏览器缓存 / 502"，却一直没发现真正的 `onFinish` 缺失。

### 12.1 复盘时间线

1. 第一版上传：用 `beforeUpload` 返回 `false` —— 文件根本进不了受控列表（坑4 的前身）。
2. 改成 `customRequest`，但**同样没写 `onChange` 同步 fileList**（坑4 本体），也没把 `onFinish` 接到 `<Form>`（坑5 本体）。
3. 用户反馈"选文件不显示 / 点存档没反应"。
4. 我做了：curl 验证后端通 → **得出结论"前端代码没问题，是浏览器连了旧实例（stale tab）"**。
5. 用户再反馈"还是不行"，我再次 curl 证明后端通，再次归咎 stale tab。
6. 直到用户说"别瞎猜，加日志"，我才**真正逐行读 `<Form>` 标签**，发现 `onFinish` 根本没挂 —— 这才是真凶。

### 12.2 为什么没早查出来（5 条根因）

**① 把"函数存在"当成了"函数已接入"**
这是最致命的思维盲区。`onFinish` 函数明明白白写在文件里，我（和初版的我）**默认它一定挂到了 `<Form>` 上**，因为"逻辑都写好了嘛"。但 React 里"定义了处理函数"和"把它作为 prop 传给组件"是两件事。漏写一个 `onFinish={...}` 编译器不会报错（`<Form>` 的 `onFinish` 是可选 prop），运行时也不抛异常——它只是安静地什么都不做。**这是最阴险的一类 bug：不报错，只是没反应。**

**② 用"环境假设"替代"代码审查"**
我有个很强的事实：curl 打后端，201、落盘，全通。于是我推理："后端没问题 → 那前端逻辑应该也没问题 → 用户看到的异常只能是环境（旧页面/缓存/端口）"。这个推理的第一环对，第二环是**跳跃的**——"后端通"完全不蕴含"前端代码正确"。前端可能自己就没把请求发出去（比如 `onFinish` 没接）。**用"环境原因"来解释一个其实属于代码的原因，是典型的归因错误。**

**③ 没有浏览器侧的第一手证据（缺日志）**
我一直有后端证据（curl），却始终**没有前端运行时证据**。用户的浏览器控制台里到底有没有报错、点存档到底触发了什么，我一无所知，只能猜。没有 ground truth，排查就是盲人摸象。

**④ 受控组件的心智模型没建立**
坑4 和坑5 本质都源于同一类认知缺口：**"一旦把某个值/列表交给 state 受控，就必须同时接好对应的回调（onChange / onFinish）来驱动它"**。当时我对 antd `Upload` 的受控机制理解不扎实，写了 `customRequest` 就以为完事，忘了 `onChange`；写了 `onFinish` 就以为完事，忘了挂到 `<Form>`。

**⑤ 验证方式不闭环**
我验证了"后端能收这张真实 PDF"（这是对的），但**没有验证"前端到后端的整条链路"**——也就是没在浏览器里真正走一遍"选文件→点存档→请求发出→成功"。缺了这最后一环的端到端验证，问题就停在"后端 OK"的假象上。

### 12.3 正确的排查方法论（请记住这 4 步）

遇到"点了没反应 / 不显示"这类**静默失败**，按这个顺序来，别跳：

1. **读代码，尤其是 JSX 标签本身**。处理函数不仅要"存在"，还要确认它**作为 prop 接到了组件上**（`onFinish={onFinish}`、`onChange={handleChange}` 都写齐了吗？）。这是最快、最常被跳过的一步。
2. **在关键路径加日志**（用户教我的）。在 `onFinish` 入口、`fetch` 前后、`catch` 里打 `console.log/error`。然后打开浏览器 `F12 → Console`，**看真实发生了什么**，而不是猜。
3. **拿真实数据端到端验证**。别只验证后端。用你手上真实的文件/输入，从 UI 走一遍完整流程；同时后端用同一份真实数据直接打接口（本项目就是用用户给的那张真实 PDF 的 base64 直连 `8787`，证明后端对它 201 + 落盘）。
4. **隔离变量**：前端现象，先查前端代码（第1、2步）；确认前端确实把请求发出了，再查网络/后端/环境。**别一上来就甩锅"缓存/端口"**——那应该是最后才怀疑的，不是第一反应。

### 12.4 给新手的"没反应"自查清单

点按钮/提交表单"没反应"时，按顺序问自己：

- [ ] 处理函数（`onFinish`/`onClick`/`onSubmit`）**写了吗**？
- [ ] 它**作为 prop 挂到组件上了吗**？（最常漏）
- [ ] 如果是表单，必填项都填了吗？校验失败会静默阻止 `onFinish`。
- [ ] 如果是受控组件（Upload/Input 绑定了 state），**`onChange` 接了吗**？state 有没有被更新？
- [ ] 打开 `F12 → Console`，有没有红色报错？我加的日志打印了吗？
- [ ] 打开 `F12 → Network`，点一下按钮，有没有发出请求？状态码是多少？
- [ ] 后端那条边，用 curl/Postman 拿真实数据直连验证过了吗？

把这 7 条过一遍，90% 的"没反应"都能在 5 分钟内定位。
